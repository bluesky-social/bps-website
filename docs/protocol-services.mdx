Bluesky runs on a "big world" public social network of user repositories: the [AT Protocol](https://atproto.com).

Many AT Protocol services and infrastructure are provided by Bluesky. They sit at different
layers, from a jetstream of everything happening right now, down to the
cryptographically verifiable raw firehose — but they all share the same open data
and the same open access. These docs describe the public protocol services and show how to build on them.

**Jetstream** is the fastest way to stream and query real network data.

## Start with Jetstream

Jetstream hands you just the slice of the network you want — posts, likes,
follows, a single account — as plain JSON over one WebSocket. No API keys, no
infrastructure to run, no binary formats to decode. The stream below is the live
network, right now:

That's the same connection you'll write in the [Jetstream
docs](/docs/jetstream): a few lines, and you're consuming the network live or
replaying it from history.

Reach for the **Relay** when you need every record with no filtering, or the
proofs to verify repository state yourself. Reach for the **app API** when you're
building against the Bluesky app's data model directly — see [API hosts and
auth](/docs/api-directory) for endpoints and authentication, or browse the [full
HTTP reference](https://endpoints.bsky.app).

## Building on the Bluesky app

If you're looking to develop against the Bluesky app — making your first post,
reading feeds, working with profiles and interactions — the [Bluesky
API](/docs/get-started) guides walk through the API step by step. You can
always come back here when you're ready to consume the network at scale.
