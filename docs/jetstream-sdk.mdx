# Jetstream SDK

Jetstream is plain JSON over a WebSocket, so you never *need* an SDK; some of our examples use CLI tools like `websocat`. But you'll tend to write the same glue each time: filtering,
reconnecting, deduping, and decoding events into typed records. For that, we
provide a **Jetstream SDK**. You construct a client, pass a filter, and
`for await` over decoded, typed events, and it handles the rest.

It's a single client for all three ways to consume Jetstream behind the same iterator: the
[live tail](/docs/jetstream), [replay](/docs/jetstream-replay), and
snapshotting.

:::note Preview
The SDK ships today as **`bsky-jetstream-preview`**, an early cut that wraps
Jetstream's **v1** live tail, the same [live tail](/docs/jetstream#quickstart-live-tail)
you can hit with `websocat`. The API shape is the one the v2 client will keep,
so what you write now carries forward. [Replay](/docs/jetstream-replay) and
snapshotting aren't wrapped yet; see [Where this is going](#where-this-is-going).
:::

## Install

```shell
npm install bsky-jetstream-preview
```

It targets Node **22.12+** and is ESM-only. The examples below run TypeScript
directly (`node index.ts`) with no build step.

## Quickstart: the live tail

Construct a `Jetstream` pointed at an instance, then iterate `.live()` with a
server-side `collections` filter. Each value is a decoded event; the record is
already parsed, so there's no `JSON.parse` step:

```ts
import { Jetstream } from 'bsky-jetstream-preview'

// https:// is upgraded to wss:// for you (a bare wss:// URL works too).
const jetstream = new Jetstream('https://jetstream2.us-east.bsky.network')

for await (const evt of jetstream.live({ collections: ['app.bsky.feed.post'] })) {
  if (evt.kind === 'commit' && evt.commit.operation === 'create') {
    console.log(evt.commit.collection, evt.commit.record)
  }
}
```


## Filtering

`.live()` takes the same two server-side filters as the raw endpoint, so a
narrow filter means less bandwidth and less work in your process:

- **`collections`**: an array of [NSIDs](https://atproto.com/specs/nsid). The
  server routes events by collection before they reach you.
- **`dids`**: restrict the stream to specific accounts.

```ts
for await (const evt of jetstream.live({
  collections: ['app.bsky.feed.post', 'app.bsky.feed.like'],
  dids: ['did:plc:ragtjsm2j2vknwkz3zp4oxrd'],
})) {
  // ...only posts and likes, only from that account
}
```

## Reacting to events

Every event carries `did`, `seq` (a monotonically increasing cursor), and a
`kind` of `commit`, `identity`, or `account`. Narrowing on `kind` narrows the type of what's inside, so `evt.commit.record`
is typed once you've checked you're holding a `create`/`update`:

```ts
for await (const evt of jetstream.live({ collections: ['app.bsky.feed.post'] })) {
  switch (evt.kind) {
    case 'commit':
      if (evt.commit.operation === 'delete') {
        console.log('deleted', evt.commit.rkey)
      } else {
        console.log('put', evt.commit.rkey, evt.commit.record)
      }
      break
    case 'identity':
      console.log('handle change', evt.did, evt.identity.handle)
      break
    case 'account':
      console.log('account status', evt.did, evt.account.active)
      break
  }
}
```

## Stopping and shutdown

Breaking out of the loop closes the socket for you. For shutdown driven from
outside the loop, pass an `AbortSignal`:

```ts
const controller = new AbortController()
process.on('SIGINT', () => controller.abort())

for await (const evt of jetstream.live({
  collections: ['app.bsky.feed.post'],
  signal: controller.signal,
})) {
  // ...
}
```

## Resuming where you left off

Each event's `seq` is a cursor. The SDK reconnects and dedups within Jetstream's
lookback window on its own, so a brief drop needs nothing from you. To resume
across a process restart, persist the last `seq` you handled and hand the SDK a
`CursorStore`. It starts the stream from just after that point:

```ts
import { Jetstream, type CursorStore } from 'bsky-jetstream-preview'

// Persist `seq` wherever you like — this one is backed by a row in your DB.
const cursor: CursorStore = {
  load: async () => db.getCursor(),   // number | undefined
  save: async (seq) => db.setCursor(seq),
}

const jetstream = new Jetstream('https://jetstream2.us-east.bsky.network')

for await (const evt of jetstream.live({ collections: ['app.bsky.feed.post'], cursor })) {
  await handle(evt)
  await cursor.save(evt.seq) // durably record progress
}
```

Delivery is **at-least-once**, so an event can arrive twice across a reconnect.
Key your writes on the record's `at://` URI (`at://{did}/{collection}/{rkey}`)
and duplicates become harmless.

## Indexing workloads

The SDK includes `LexIndexer` and `JetstreamRunner`. You
register a handler per collection and the runner drives the stream, validating
records against their [lexicon](https://atproto.com/guides/lexicon), preserving
per-record order, and checkpointing the cursor for you:

```ts
import { Jetstream, LexIndexer, MemoryCursorStore } from 'bsky-jetstream-preview'
import { app } from '@bsky.app/sdk/lexicons' // schema-typed collections

const jetstream = new Jetstream('https://jetstream2.us-east.bsky.network')

const indexer = new LexIndexer()
  .commit(app.bsky.feed.like, {
    put: async (e) => console.log('index', e.uri, e.record),
    del: async (e) => console.log('remove', e.uri),
  })
  .identity(async (e) => console.log('identity change', e.did, e.handle))

// Swap MemoryCursorStore for your own CursorStore to persist across restarts.
await jetstream.runner(indexer).live({ cursor: new MemoryCursorStore() })
```

:::note
`LexIndexer.commit()` keys off a lexicon schema (which is what types and
validates the records it hands your `put` handler). Those schemas ship in the
SDK's companion lexicons package. The live
tail above needs none of that; plain collection strings are enough.
:::
